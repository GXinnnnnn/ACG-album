# 安装与使用

本文适用于 Windows x64。当前为 **1.2.1 · 2026-11-06 同版本修订**，将此前本机 1.2.2 开发成果并入现有 v1.2.1 发布，不新增版本；变化见 [1.2.1 说明](RELEASE_NOTES_1.2.1.md)，完整功能见 [README](../README.md)。本轮沿用下方三版原文件名替换附件，需按替换发布随附的新大小与 SHA-256 清单核对下载文件。同名旧文件不能代表本次修订，源码和成品的正式验收以待发布的 `VALIDATION_REPORT.md` 为准。

## 选择安装包

打开 [1.2.1 发布页](https://github.com/GXinnnnnn/ACG-album/releases/tag/v1.2.1)，三种安装包选择一种即可：

| 版本     | 下载                                                                                                                                     | 随附内容                                                   |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| Standard | [ACG-album-Setup-1.2.1-Standard.exe](https://github.com/GXinnnnnn/ACG-album/releases/download/v1.2.1/ACG-album-Setup-1.2.1-Standard.exe) | 软件本体，不附带离线 Bangumi 索引，可联网匹配              |
| Lite     | [ACG-album-Setup-1.2.1-Lite.exe](https://github.com/GXinnnnnn/ACG-album/releases/download/v1.2.1/ACG-album-Setup-1.2.1-Lite.exe)         | 软件本体与精简名称、别名、类型及关联索引，日常使用推荐     |
| Full     | [ACG-album-Setup-1.2.1-Full.exe](https://github.com/GXinnnnnn/ACG-album/releases/download/v1.2.1/ACG-album-Setup-1.2.1-Full.exe)         | 软件本体与完整离线资料，额外保留长简介、infobox 和原始记录 |

Lite 和 Full 的名称覆盖及匹配规则相同，Full 不会仅因资料更完整而提高识别准确度。所有版本都不附带封面图片；在线封面、当前详情和受限条目访问仍取决于网络及账号权限。数据库快照、来源与占用说明见 [本地检索数据说明](LOCAL_SEARCH_DATA.md)。最终安装包大小、随附索引和 SHA-256 以正式发布附件为准。

历史附件在 [全部 Releases](https://github.com/GXinnnnnn/ACG-album/releases) 中保留。升级时下载对应版本的完整安装包，不要将旧附件改名为新版。

## 首次安装

1. 下载所选完整安装包。按 Release 校验清单核对大小和 SHA-256；PowerShell 可使用 `Get-FileHash -Algorithm SHA256 <安装包路径>` 查看摘要。
2. 运行安装程序，选择安装位置。安装目录存放程序与随附索引；个人资料和原始图库有各自的位置。
3. 启动后点击侧栏「导入」，选择作品、角色或普通图片目录，按需启用 Bangumi 匹配与作品类型。普通照片可以关闭条目匹配。
4. 保持原收藏目录结构，选择根目录。后台逐步建立索引，已出现的卡片可以先浏览。扫描完成后，联网资料队列可能仍在继续。
5. 需要访问受限资料时，在「偏好设置 → 作品简介」配置自己的 Bangumi Access Token。网页登录状态不会自动转为 API 授权，应用不提供共享 Token。

安装器未申请发行者代码签名，Windows 可能显示未知发布者。请核对下载来源与摘要；不要仅凭文件名判断来源。程序、Full 索引、缓存和安装临时文件都需要磁盘空间，安装包下载体积不能代表安装后的总占用。

## 升级或切换版本

Standard、Lite、Full 使用同一应用身份与个人资料格式。退出相册后运行目标版安装包，选择原安装位置即可覆盖切换；不需要同时安装三份。

升级前先完成以下操作：

1. 从「偏好设置 → 缓存与资料库」确认实际资料目录和缓存目录。
2. 通过程序正常退出，等待相册进程结束，再备份完整资料目录。不要只复制仍在写入的 `library.sqlite`；SQLite 的 WAL 文件可能包含尚未合并的记录。
3. 原始图片、视频和目录另行备份。若缓存另存，希望保留已下载封面、简介与缩略图，也备份实际缓存目录。
4. 保留原启动器的 `ACG_DATA_DIR` 等资料参数，避免升级后误用空目录。安装目标应是程序目录，不能用个人资料或原图目录作为安装目录。

**本次为 1.2.1 同版本替换，已经安装同号版本时不会自动提示升版。请从上方 v1.2.1 发布页手动下载修订后的 Standard / Lite / Full 完整安装包，核对新校验清单，退出程序后覆盖安装。** 历史本机显示 1.2.2 的程序也需手动覆盖获取正式修订，不能依赖更高版本提示。

应用内「检查更新」读取正式 Release。本体载荷、资源身份、平台、数据版本和读取兼容性均通过校验时，可以仅下载本体并保留原索引；缺少可信清单、资源变化或需要切换版型时提供完整安装包或 GitHub 手动下载入口。版型按实际随包索引识别，只有确认索引目录不存在才判为 Standard；清单损坏、未知协议或路径不可信时停止默认下载，需明确选择。

由用户确认下载与安装，弹窗显示实际字节进度、失败说明和可点击的 GitHub 发布链接。自动安装还要求当前程序有可信的逐文件运行时所有权清单，完整安装器必须生成目标版本的新清单；安装与回滚按文件大小和 SHA-256 验证。缺少清单、存在未知文件或校验失败时停止自动安装，按发布页提示手动完整覆盖；旧安装器没有新协议清单时不能直接视为支持自动安装。失败恢复原程序与资源，保留原随包索引、个人资料和本机五份私有字体。普通 Standard 安装器不能当作保留 Full 资源的本体更新包。

「本地资料检索 → 资料库补全 / 下载」继续提供 Lite / Full 入口。卸载默认保留应用数据。真实 Windows NSIS 覆盖安装、UAC 与系统重启全链路尚未在用户环境端到端实测；本轮正式验收以替换发布随附的报告为准。

旧版本可能不识别新版数据库字段。需要回退时先保留当前完整备份，再使用与旧程序对应的资料副本；不要让旧程序反复写入唯一一份新版资料库。

## 启动、继续任务与取消

已有资料库启动时先读取保存的目录、设置和任务状态，显示真实缓存内容；统计和离线索引状态随后加载。后台整理、未完成索引和资料补全在页面出现后继续。首次导入还没有缓存的内容，需要等待实际扫描结果。

| 操作或状态                   | 含义                                                             |
| ---------------------------- | ---------------------------------------------------------------- |
| 程序正常退出、正常关机       | 保留未完成扫描和待补资料，下次启动继续                           |
| 点击任务「取消」             | 明确终止当前批次，不在重启时自动重开；已建立的索引和整理结果保留 |
| 目录离线、权限不足、任务受阻 | 保留状态并显示原因，先恢复磁盘或权限，再使用状态提示中的重试入口 |
| 网络限流、凭证问题           | 资料补全可暂停，按提示等待、处理凭证或重试；本地缓存仍可浏览     |
| 强制终止、断电、存储损坏     | 不作无损续作保证；保留资料和原目录，先检查实际状态               |

导入选择、扫描、资料补齐和取消收尾期间，添加按钮显示忙状态。取消请求发出后，系统仍需完成正在处理的步骤；等待状态结束，再开始新导入。不要把明确取消当作暂停按钮。

## 卡片大小、目录树与排序

新资料库首次打开时使用当前窗口的「中」卡片；尚未调整时，最大化或改变窗口宽度会继续使用适配后的中档。手动点击档位、拖动尺寸滑杆或使用 Ctrl＋滚轮后，会保存实际数值，下次打开恢复最后选择；点击当前中档也会记住它。旧资料中已经明确保存的尺寸继续优先，不会因升级统一改成中档。

左侧展开的目录树连续滚动，只列出文件夹；窗口变矮时仍保留底部状态区。后台索引和目录变化校验期间继续显示已加载的列表，新增、移除与改名结果在校验完成后更新。导入尚未发现的目录仍需等待实际扫描结果。

导入根目录所列一级相册默认名称升序，进入一级相册及其后代目录默认内容日期倒序；以导入根身份判定层级。明确选择的排序和方向按当前页面与目录分别记忆，即使点击当前默认值也会保存，优先于默认规则。按日期排序时文件夹优先，文件夹使用创建时间，带可用拍摄信息的照片使用拍摄时间，其他文件使用有效文件系统时间；缺失创建时间时回退修改时间。创建日期和修改日期还可以独立选择，时间线继续按拍摄月份组织。

父子相册往返先恢复真实卡片、已解码封面和滚动位置，再按数据代次（epoch）校验刷新；最多保留两个非活动视图、共享 180 张卡片，每个视图最多七页数据与高度摘要。超出缓存预算、尺寸变化或真实数据变动时可能重新加载或测量，不保证所有页面永久留在内存。

日期准备未完成时先显示名称升序。`migrateAsync` 默认每批回填 512 条，上限 4096 条，批次间让出执行并保存续作位置；右下角显示读取、已提交数量、两个索引的建立阶段和失败状态。SQLite 的 `COUNT` 与单次 `CREATE INDEX` 仍同步执行，不能将分批回填理解为全程无阻塞，索引阶段也不虚构整体百分比。液态／磨砂玻璃及原有外观选择继续保留；Everything 仅作评估，本轮没有集成。

## 重命名与刷新

右键文件夹、图片或视频选择「重命名…」，核对显示的真实路径。媒体扩展名固定保留，只编辑名称；Enter 提交，Esc 关闭对话框。提交会修改磁盘上的真实文件或目录，并同步应用中的关联、收藏、手动封面、裁切与缓存记录。只修改作品关联或自定义角色名称不会重命名磁盘文件。

不支持把名称输入框当作移动路径使用。非法 Windows 名称、目标重名、文件占用、权限或导入任务冲突会显示错误；先处理原因再重试，不会自动覆盖同名目标。若提示改名需要恢复或磁盘名称已更新但页面失败，请按提示检查实际路径并刷新，不要反复改动或删除恢复涉及的文件。超长路径、特殊文件系统、网络盘和所有 Windows 配置组合尚无全面兼容承诺。

工具栏卡片尺寸右侧的刷新按钮与页面右键刷新入口都会检查磁盘目录变化，补入新增内容并处理已移走条目。普通浏览时可使用 F5 / Ctrl＋R；输入、弹窗或查看器中保留原快捷键行为。未变化的卡片和图片会尽量复用。外部工具移动或重命名目录后需要刷新核对，不能保证与应用内改名保留关联的行为完全相同。

## 数据位置、隐私与字体

新资料默认保存在 Windows「文档」中的 `ACG-album`，实际位置以设置页为准；既有资料发现和启动器的 `ACG_DATA_DIR` 可能使路径不同。随包 Bangumi 数据位于程序 `resources/local-index`，以只读方式使用，个人整理结果不会写入该随包数据库。

缓存通常分为在线封面 `covers`、缩略图 `thumbnails` 和简介 `metadata`。缓存位置可在设置中迁移；迁移缓存不会搬动个人数据库或原图。清空缓存保留关联、收藏和裁切等整理参数，但之后浏览与在线补齐仍需重新生成或下载相应文件。

Bangumi 匹配会发送检索词或条目 ID，并下载资料和封面；关闭联网匹配可进行本地导入和浏览。检查更新会连接配置的 GitHub 仓库。Token 在 Windows 使用 Electron `safeStorage` 加密，换电脑或账号后可能需要重新绑定；不要公开个人数据库、Token、应用日志或私有图库路径。

公开源码与安装器不附带方正专有 TTF。程序优先使用本机可用的指定字体，缺少时回退系统字体；可在「偏好设置 → 外观 → 全局字体」选择已安装字体。维护者的本机交付可保留已有本地字形和个人选择，这不表示公开版获得了字体再分发授权。

## 遇到问题

- 找不到原收藏：先检查资料目录、启动器参数和原磁盘是否仍可访问，避免立即清库或重新创建唯一资料副本。
- 搜索结果不确定：手动选择正确条目并保存；「100% 相关」是名称相关提示，不代表已经完成关联。
- 手动关联后资料尚未齐全：关联先保存，封面与详情后台补全；已有批量导入的进度仍会正常显示。
- 视频内播失败：可交给系统默认播放器；媒体兼容范围见 [媒体兼容说明](MEDIA_COMPATIBILITY.md)。

反馈问题时提供版本、版型、操作步骤和脱敏错误信息。历史验证与本轮最终验收状态分别记录，不用历史耗时推算个人图库的启动或扫描速度。
