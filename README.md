# ACG-album

**给硬盘里的 ACG 收藏，一个想常常打开的相册。**

ACG-album 是为 ACG「囤囤鼠」准备的 Windows 本地相册。游戏 CG、角色插画、动画截图、设定集，或是日常照片，都能直接沿用现有文件夹整理：导入收藏目录，把一排排文件夹变成封面卡片，打开就是连续浏览的媒体瀑布流。

**按作品、角色归档的收藏，还可以配上对应的 Bangumi 封面与资料。** 看封面找作品，翻相册看收藏；需要时再手动关联条目、挑选本地封面、调整显示位置，或填写角色名称与简介。已经整理好的目录层级，成为相册的一部分。

柔和配色与深浅主题陪你翻收藏，动效强度和磨砂玻璃按喜好选择。卡片随窗口均分铺满，4K 宽屏也能利用起来；长图保留顶部预览，点开再看完整原图。原始文件留在原处，收藏、人工关联与封面裁切等整理结果保存在本机，升级时继续保留。

## 功能亮点

### 文件夹就是相册

- **卡片式浏览本地目录**：保留原有文件夹结构，用封面、标题、媒体数量和条目资料呈现收藏；支持逐层进入子目录。
- **批量导入，边扫边看**：导入收藏根目录后，子目录逐层成为相册。索引在后台分批建立，已载入的内容可以继续浏览，右下角显示扫描与资料匹配进度，并支持取消。
- **文件夹与媒体连续浏览**：统一浏览图片、GIF、动态 WebP 与视频；切换卡片尺寸、详情模式和紧凑瀑布流，保留滚动位置。
- **卡片大小随手调**：右上角工具栏可切换小、中、大卡片，在「查看设置」窗口调整封面比例；浏览区按住 **Ctrl＋滚轮** 也能调整大小。各列均分可用宽度，适配 4K 宽屏。媒体保持同列宽的瀑布流，卡片总高度不超过同宽文件夹卡片的两倍；超长缩略图从顶部裁尾，查看原图不受影响。切换尺寸保留正在浏览的位置，并记住选择。
- **大图库增量维护**：重扫时复用未变化条目的索引与缓存，补齐新增或变动内容，清理已移走目录的失效记录。后台刷新保留未变化的卡片，减少图片重复载入。

### 为作品与角色收藏补齐资料

- **一级作品 / 角色目录批量匹配**：导入时选择目录类型，自动处理分类下的一级作品或角色文件夹；作品可限定动画、书籍 / 漫画、游戏、三次元等类别。后代目录可手动关联。
- **完整原名优先**：作品先以完整文件夹名称检索，保留中日英文、数字与标点，仅先处理末尾括号附注及末尾「系列」。原名没有高匹配候选时，再尝试双语拆分与清理后的名称；续作编号和作品类型仍参与判断。
- **没匹配好，先看本地收藏**：父目录没有高匹配时，最多再尝试少量直接子目录名称，为父目录寻找关联，子目录本身不自动绑定。仍无合格结果时，使用按本地文件名自然顺序排列的首张图片作为封面，之后也可手动关联或换封面。
- **角色封面批量选择**：角色目录可以统一使用按名称自然顺序排列的第一张本地图片，或 Bangumi 角色立绘。没有合适立绘时回退本地首图；后续增量扫描保留选择，手动指定的封面与裁切优先。
- **本地资料与在线补齐**：Lite / Full 可利用随包索引识别名称；联网匹配再按条目 ID 补齐详情与封面。未安装索引包的 Standard 仍可联网使用。
- **中、日、英文名称检索**：结合原名、译名、别名和作品类型判断候选；角色采用唯一精确名称判定，存在歧义或候选不完整时留给人工选择。
- **成功匹配自动确认**：勾选 Bangumi 匹配并成功关联作品或角色后，自动确认封面，不再要求匹配度恰好为 100%；仅未关联条目、使用本地兜底封面且尚未确认的文件夹显示红点。升级也会修复已有匹配记录的旧红点。
- **相近候选按收藏人数与发行日期选择**：作品导入在完整召回的合格候选中，将距最高匹配度不超过 3 个百分点的条目一并比较；人数接近时，从达到最高收藏人数 90% 的条目中选有效发行日期最新者。保留作品类型与续作识别检查；角色仍采用唯一精确名称判定。
- **当前目录批量确认封面**：打开目录，点击右上角卡片尺寸旁的滑杆图标，在尺寸设置下方点击 **「批量确认封面」**。一次确认该目录下全部直接子文件夹的封面，包含未加载项目，不受搜索、收藏或媒体筛选限制，重启后保留；不递归确认后代目录。首页同时确认当前页范围内的分类及已展开的相册预览，右键也可逐项确认。
- **手动整理优先**：右键相册可更改作品关联、检索并选择角色，或填写自定义角色名称与简介。刷新与自动补齐资料时保留人工整理结果。
- **封面自己选，位置可微调**：右键相册选择「更换封面…」指定本地图片，再用「调整封面位置…」拖动位置、滚轮缩放，或通过滑条精确调整；支持恢复居中及恢复自动封面，仅改变卡片显示，不裁掉原图。
- **独立本地资料检索**：从侧栏搜索作品、人物和角色，用作品类型或所属作品 ID 缩小范围；完整版可展开更完整的离线摘要。

### 让收藏更好看，也更好找

- **深浅主题与可选玻璃**：柔和粉色、圆角卡片与统一的侧栏、弹窗和进度反馈。**「液态玻璃」** 默认为侧栏和顶部悬浮组件加入通透磨砂与高光；可在右上角「偏好设置」中关闭，恢复静态材质，并记住选择。
- **低 / 中 / 高三档卡片动效**：在「偏好设置 → 动效强度」中选择：低档关闭卡片过渡，仅轻微缩放，并减少侧栏、弹窗等非必要动画；中档平滑聚焦放大；高档整张卡片轻微放大，并随鼠标位置进行轻微 3D 跟随。默认中档，3D 跟随仅用于鼠标；动效遵循系统的「减少动态效果」偏好。
- **搜索与收藏**：按名称检索，按实际文件 / 文件夹原名自然排序（例如 2 在 10 前），也可按创建日期、修改日期或大小升降序排列；作品资料标题不改变文件名排序。收藏常看内容，使用多层目录树定位相册。
- **空白处右键菜单**：浏览区空白处可刷新页面、增量更新、切换排序、调整卡片尺寸、批量确认或导入目录；菜单跟随明暗主题，支持方向键、Home / End、Escape 与 Shift＋F10。
- **匹配结果分批刷新**：后台每完成 10 个不同文件夹的匹配合并刷新，任务结束或暂停时补刷新最后一批；手动关联和封面修改即时显示。
- **时间线浏览**：全库或指定相册及其子目录可按月份、本地地点筛选，优先使用 EXIF 拍摄时间。
- **原图与媒体查看**：双击打开查看器，方向键切换、滚轮缩放、拖动平移；视频使用 Chromium 播放控件，不支持的编码可交给系统应用。
- **图片可以直接编辑**：右键图片选择「编辑副本…」，拖动裁剪框或输入精确坐标，选择常用比例，旋转、调整导出尺寸，以及亮度、对比度与饱和度；对照预览后另存 PNG / JPEG / WebP / GIF，编辑器拒绝覆盖原件。
- **GIF 与动态 WebP 也能调**：同一编辑器支持播放预览、逐帧查看、截取起止帧、统一帧时长和设置循环次数；可以导出动画副本，或把当前帧另存 PNG。时长留空保留原逐帧延时；GIF 时长按 10 ms 精度处理，APNG 仅支持静态帧编辑。
- **缓存位置可管理**：在右上角「偏好设置 → 缓存与资料库」查看实际路径与占用，打开缓存目录、更换存储位置、恢复默认位置，或清空后重建。

## 开始使用

1. 在 Standard、Lite、Full 中选择一版安装并启动 ACG-album。需要本地名称检索时推荐 Lite。
2. 点击侧栏「导入」，选择作品、角色或普通图片目录。需要自动补齐资料时启用 Bangumi 匹配，并选择相应作品类型；角色目录可选择本地首图或 Bangumi 立绘作为封面来源。
3. 选择收藏根目录，等待目录索引建立，期间可浏览已经出现的相册。扫描与在线资料匹配是两个阶段，扫描完成后资料队列可能仍在继续。
4. 右键相册可修改类型、手动关联条目、填写角色资料，或选择和裁切本地封面。
5. 从侧栏进入「本地资料检索」查找作品、人物、角色；从右上角偏好设置调整外观、Token 与缓存位置。

自动匹配不能保证识别所有文件夹名称。缩写、非官方译名、复杂备注或同名条目可通过手动关联修正。普通照片相册可以关闭条目匹配。

公开条目通常可匿名查询。部分条目需要具有相应权限的 **Bangumi Access Token**；网页登录状态不会自动用于 API，是否可访问由 Bangumi 服务端与账号权限决定。应用不内置共享凭证。

## 数据与缓存

- **收藏留在原处**：浏览、索引、条目关联和封面调整不会移动、重命名或删除导入的原始文件；封面裁切只保存显示参数，移除分类只移除索引。
- **整理结果保存在本机**：新资料的默认目录为系统「文档」中的 `ACG-album`，保存资料库、设置、手动元数据和加密 Token。应用中可通过「缓存与资料库 → 打开资料目录」查看实际位置。
- **下载封面与浏览缓存**：默认位于资料目录的 `covers`（在线封面）、`thumbnails`（缩略图）和 `metadata`（简介文件）中。设置会显示实际缓存目录及三类文件的占用；更换位置时会把现有缓存迁移至所选目录下的 `ACG-album-cache` 文件夹。
- **清空与重建**：可以清理未使用缓存、单独清空缩略图或简介，也可以一并清空上述三类缓存。原始文件、收藏、条目关联、手动封面与裁切参数会保留；缩略图在浏览时重建，在线封面与简介可重新同步。缓存迁移不会搬动资料库。
- **备份**：备份实际资料目录可保留整理结果；如果缓存另存到其他磁盘，希望一并保留已下载资料时，也请备份对应缓存目录。
- **按需联网**：Bangumi 匹配会向相应服务发送检索词或条目 ID，并下载详情与封面。关闭联网匹配的导入可在本地进行，离线也能浏览已索引内容。
- **凭证在本机管理**：Windows 上的 Bangumi Token 使用 Electron `safeStorage` 加密保存，变更账号后隔离查询缓存。请勿将个人资料目录、Token 或图库提交到仓库。
- **副本导出**：编辑导出为新文件，转为 SDR sRGB，并移除 EXIF / GPS；不会修改原件。

检查更新由用户手动触发，默认连接官方仓库 [GXinnnnnn/ACG-album](https://github.com/GXinnnnnn/ACG-album) 的正式 Releases。新安装与旧版空配置均自动使用该仓库，已保存的自定义更新仓库会保留；也可填写 GitHub `owner/repository` 或仓库地址修改来源。GitHub API 限流时会尝试公开的最新正式发布入口，连接失败会明确提示。应用本身不自动下载或安装更新。

「本地资料检索」中的「资料库补全 / 下载」提供官方仓库内与当前软件版本对应的 Lite、Full 安装包及发布说明。Standard 用户可选择其中一版，退出程序后覆盖安装以补全随附索引；Lite 用户也可切换 Full 获取更多摘要等资料，个人相册与整理结果会保留。两种索引的名称检索覆盖相同。

## 开发与构建

建议环境：**Windows x64、Node.js 24、pnpm 11**。主要依赖为 Electron 40.10.6、Sharp 0.34.5、exifr 7.1.3，索引使用 SQLite WAL 与 trigram FTS5。模块分工见 [项目结构](docs/PROJECT_LAYOUT.md)。

```powershell
pnpm install --frozen-lockfile --ignore-scripts
node node_modules/electron/install.js
pnpm start
```

运行测试与基础构建：

```powershell
pnpm test
pnpm run format:check
pnpm run package:dir
pnpm run package:installer
```

`package:installer` 是基础程序构建，不会自动下载离线资料库。与 Releases 一致命名的纯软件版使用 `pnpm run package:standard` 构建，随后可用 `pnpm run verify:standard` 隔离验证。精简 / 完整两版使用 `pnpm run package:search` 构建，随后可用 `pnpm run verify:search` 从安装包解压并隔离验证。双版构建脚本读取预处理的 Archive 数据及校验清单，运行前需根据 [本地检索数据说明](docs/LOCAL_SEARCH_DATA.md) 准备数据，并通过 `ACG_INDEX_SOURCE` 指定目录；源码仓库不包含大型数据库、安装包、个人图库或本地测试报告。

Electron 安装脚本在首次准备运行时下载所需运行时。若环境设置了 `ELECTRON_RUN_AS_NODE`，启动 GUI 前需移除。构建默认使用 `--publish never`；提交源码不会自动发布安装包。

### 验证与性能

自动化回归覆盖本地索引、匹配、导入、缓存和十万文件隔离用例。安装包验收从最终安装文件解压程序，在独立资料目录检查启动、明暗主题、窄窗口进度布局、导入与失效目录清理；Lite / Full 另核对真实资料检索、类型限制与候选一致性，Standard 核对未安装本地索引时的提示。验收不覆盖正式安装或私人相册。

十万文件用例使用空 JPEG 占位文件测量文件系统索引与数据库响应，**不代表真实图片解码或 Bangumi 联网同步速度，也不能外推到百万真实图片的处理时间**。虚拟网格按需保留可见卡片与邻近页，减少无关 DOM 与图片重建。启动、索引与在线请求的实测范围和复现方法见 [性能说明](docs/PERFORMANCE.md)；详细验证结果随对应 Release 提供，维护者的完整诊断报告不混入源码。

GUI 与性能脚本应逐个运行。部分维护脚本包含维护者本机路径或系统集成操作，使用前请检查目标；`check-installer.cjs` 会进行临时安装与卸载，不能在已有同名正式安装的机器上直接运行。

### 格式与使用边界

- 常见 JPEG、PNG、WebP、GIF、BMP、TIFF、AVIF 可索引；HEIC / HEIF 解码依赖具体编码和 Sharp 构建，视频播放取决于 Chromium 支持的容器与编码。
- APNG 目前仅可靠支持静态提取，不提供可靠的 APNG 多帧编辑导出。
- 高位深与宽色域会显示相关提示；缩略图和编辑副本为 SDR，尚未验证 HDR 显示器的端到端输出。
- 实际滚动、导入和解码速度受磁盘、媒体格式、缓存与窗口环境影响，不承诺任意规模图库或固定 4K 60fps。
- Bangumi API 资料请求按至少约 1.05 秒间隔串行，并处理限流与退避；大批量不同条目的资料同步可能需要较长时间。
